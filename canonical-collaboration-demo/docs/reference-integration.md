# Reference integration inventory

This inventory separates native SuperDoc calls, demo-owned agent tools, and compatibility workarounds. A native Word field or footnote in the exported file does **not** imply its mutation used a native Document API: several paths below edit OOXML snapshots. The code is now copyable from `server/src/reference-integration/` and `client/src/reference-integration/`. See [Customer integration](customer-integration.md) for the host contracts and export command. Bare server paths below are relative to the portable server folder.

## Native API usage

The demo uses the SDK's Full agent toolkit, inspect/search/read operations, native source CRUD, citation/field reads, native tracked-change decisions, collaborative document save/replace, browser selections, and `ui.viewport.getRect`. Hocuspocus provides shared document transport. Cursor-based toolbar selections come from the browser API; highlight rectangles come from the native viewport API. Native citation deletion is attempted before its unsupported-context fallback.

## Agent tool inventory

The model receives exactly five functions:

| Origin | Tool | Execution |
| --- | --- | --- |
| Full preset | `superdoc_inspect` | Native inspection |
| Full preset | `superdoc_perform_action` | Native actions, including `insert_footnote`; ordinary prose actions are filtered for streaming |
| Full preset | `superdoc_api_search` | Discover native operations and parameter schemas |
| Full preset | `superdoc_api_call` | Native reads, mutations, and ordered batches, including sources, citations and bibliographies |
| Custom | `superdoc_stream_text` | Incremental prose through the native streaming writer |

There are no separate agent tools for source CRUD, citation insertion, footnote insertion, or bibliography management. Source creation/update/removal uses `doc.citations.sources.*`. Bibliographies use `doc.citations.bibliography.insert/get/configure/rebuild/remove`.

`native/reference-api.js` applies host policies behind the native dispatcher: source metadata is saved directly in either edit mode; unsupported direct document edits are still refused in Reviewing mode; source removal checks for citations at invocation time, including citations created earlier in the same batch. The SDK retains argument validation and ordered batch receipts. Only successful, non-preview mutation receipts trigger post-processing. Partial batches report earlier successful writes without claiming the failed operation completed.

`reference-document.js` retains the existing source/bibliography helpers for toolbar HTTP operations. Their input validation lives under `native/`; those helpers are not registered model tools. Native citation insertions/updates/removals, source updates/removals, and bibliography operations invoke the app's CSL formatting internally. Citation caches receive a separating space when adjacent to prose; existing whitespace and opening punctuation are preserved. Complex bibliography fields created by the renderer are normalized to independent simple fields when the SDK explicitly refuses them, then the native operation executes and CSL layout is restored. Preview operations do not use this mutating compatibility path.

The UI reads the native source catalog. `/document-events` sends document-scoped invalidations from the collaboration server, including metadata-only edits from other clients. The app debounces these notifications and refreshes on reconnect, room/document changes, and existing toolbar/agent completion touchpoints. It does not maintain a separate reference store.

Native citation insertion remains direct-only in SDK 2.29.0-next.14; native footnote insertion supports direct and tracked modes. Existing import/export, toolbar insertion, rendering, deletion, and browser compatibility fixes remain independent of the model tool list.

## Compatibility and placement workarounds

| ID | Problem and demo behavior | Owner / removal condition |
| --- | --- | --- |
| ANCHOR-01 | Models guessed numeric offsets, splitting words and confusing a section's first and last paragraphs. The wrapper snapshot insertion methods accept an exact `afterText` quote, `sectionEnd` heading, or inspected `paragraphEnd` ID. The host resolves visible UTF-16 coordinates against the current snapshot, follows real heading levels, rejects absent/ambiguous anchors, and returns surrounding text as evidence. | `server/src/reference-integration/workarounds/reference-anchors.js`; retain deterministic placement even if the transport later becomes native search handles. Current section resolution covers top-level body paragraphs; unsupported or ambiguous scopes fail. |
| ANCHOR-02 | A successful mutation alone is insufficient evidence of placement. Before applying the snapshot, verify the exact citation instruction or footnote ID at the resolved paragraph/offset. The resolver and inserter share one visible-text scanner, excluding deleted text and counting existing markers. | `workarounds/reference-anchors.js`, `workarounds/footnote-insert.js`, `reference-document.js`; replace only with an equally verified native targeting path. |
| AGENT-RECOVERY-01 | Malformed anchors caused inspect/retry loops until turn exhaustion. Snapshot anchor validation identifies missing/conflicting fields; native agent calls use the SDK validation contract. Generic retry policy stops the second identical failure, and interruption reports use actual successful receipts. Fresh mutation revisions can be reused without redundant inspections when the semantic target is already known. | `tools/reference-anchor-contract.js`, `agent/tool-errors.js`, `agent/agent-run-progress.js`, `agent/reference-tool-progress.js`; demo tool-contract and orchestration safeguards, independent of OOXML compatibility workarounds. |
| REVIEW-01 | SuperDoc 2.18 maps structural footnote insertions to the table caption, despite native `footnote-insertion` semantics. The local adapter sets `Added footnote` only on tracked review records with the exact `footnote insertion` excerpt and erroneous `tableInsert` display type. It preserves IDs, review actions, and document content. | `client/src/reference-integration/components/FootnoteReviewLabels.tsx`, `client/src/reference-integration/workarounds/footnote-review-labels.ts`; remove when native captions handle footnotes. This is a presentation-model compatibility workaround: `getComment` is public, but writing its `trackedChangeLabel` is not a dedicated supported caption API. DOM observation discovers newly mounted review cards; it does not rewrite document DOM. |
| TYPING-01 | Replacing part of an ordinary word after earlier pending deletions in the same paragraph can split subsequent typing across deletion-side text. In Reviewing mode, before the first plain printable key, normalize a tracked-space selection using the public API's existing visible range and `ui.selection.apply`. The native keyboard handler then owns all typing, formatting, revisions, author identity, and history. Cache the source selection so rapid keys cannot reapply an outdated range. | `client/src/reference-integration/workarounds/tracked-replacement-caret.ts`; thin React lifecycle wiring in `client/src/reference-integration/components/TrackedReplacementCaret.tsx`. This is a browser selection remediation using native APIs, not an agent tool or document snapshot edit. Remove after native keyboard replacements retain correct coordinate provenance with earlier revisions. |
| SOURCE-01 | The native source catalog is authoritative. Import old Word source records with native `citations.sources.insert`, map original Word tags to native IDs, and remap existing field instructions without changing their displayed text. Preserve original tags, corporate-author structure and opaque XML in an app-owned custom XML part; snapshots/export regenerate supported fields from the current native list. Native-created/updated/deleted sources are visible to both the UI and agent. Ordinary source CRUD uses native operations; metadata updates/removals may subsequently refresh cached field rendering. | `native/reference-sources.js`, `workarounds/citation-import.js`; the import/export preservation bridge remains until the SDK preserves the same legacy tags and opaque metadata itself. |
| CITE-01 | Native citation insertion/source lookup rejected valid collaborative contexts or temporary IDs. The toolbar still inserts a Word `CITATION` field through a revision-checked snapshot. Its source IDs are now native IDs. Agent citation insertion uses the Full preset native API instead. | `server/src/reference-integration/workarounds/citation-insert.js`; retire after native insertion works with persisted source tags in the same collaboration lane. |
| NOTE-01 | Native insertion could fail in paragraphs containing fields, and exports could wrap the footnote part in `document/body`. The toolbar still inserts real footnote XML and relationships while preserving fields; normalize only the recognized erroneous part wrapper. The agent uses native Full-preset footnote insertion. Native numbering and structural review remain native. | `server/src/reference-integration/workarounds/footnote-insert.js`; retire after native insertion and part export handle the same fixtures. |
| RENDER-01 | Style changes and field display need reliable results. Vendored CSL styles and citeproc render APA/Chicago/MLA caches while preserving native instructions, tracked revisions, and editable field-code display. | `server/src/reference-integration/workarounds/reference-rendering.js`; retire when native formatting/display supports the same styles and round trips. |
| DELETE-CITE-01 | Keyboard deletion of the last citation character can be rejected while the field remains. Intercept exact citation deletion, try native `citations.remove`, then use the snapshot fallback on `unsupported-context`, including tracked deletion when requested. | `client/src/reference-integration/components/CitationDeletion.tsx`, `server/src/reference-integration/workarounds/citation-remove.js`; retire when keyboard/native removal handles these contexts. |
| DELETE-BIB-01 | Bibliography text can disappear while its empty field/paragraph persists. Remove the complete generated field and paragraphs; handle backspace/delete on a confirmed empty field in Editing mode, retaining sources, in-text citations, and independent headings. | `client/src/reference-integration/components/BibliographyDeletion.tsx`, `server/src/reference-integration/workarounds/bibliography-remove.js`; retire when native keyboard/field removal handles the same cases. |
| BIB-READ-01 | SDK field filtering and bibliography IDs could produce false matches or `not found`. Discover fields by their actual `BIBLIOGRAPHY` instruction and address the containing paragraph. | `server/src/reference-integration/workarounds/bibliography-read.js`; retire after native discovery/addressing works across reloads. |
| BIB-CREATE-01 | Bibliography insertion encountered style-part/ambiguous-paragraph errors. Create the native field in a snapshot, avoiding SDK insertion style resolution. Generated entries inherit the field paragraph's style or document default instead of assuming a `Bibliography` style exists. | `server/src/reference-integration/workarounds/bibliography-insert.js`, `server/src/reference-integration/workarounds/reference-rendering.js`; retire after native insertion handles these style contexts. |
| XML-01 | Snapshot serialization can lose original namespace declarations. Preserve document namespaces across round trips. | `server/src/reference-integration/workarounds/reference-rendering.js`; retire only when exported parts preserve their namespace dependencies. |
| NOTE-LOCATION-01 | Navigation must target superscript body references, rather than the note text near page footers. Scan exported reference locations, then use native selection/viewport geometry for navigation and highlights. | `client/src/reference-integration/workarounds/footnotes.ts`, `client/src/reference-integration/components/FootnoteNavigation.tsx`, `client/src/reference-integration/components/FootnoteHighlights.tsx`; retire the scan when native reads expose reliable body-reference anchors. |

Snapshot mutations are serialized and checked against the current revision before application. Observed stale requests fail. The final check and replacement are not atomic; a host write fence is needed to prevent browser edits racing that window. Snapshot replacement is a compatibility transport, not a granular native mutation; preserving native review semantics needs continued round-trip verification.

The typing remediation is intentionally scoped to ready, non-empty, single-paragraph tracked selections whose native visible range has the same length. It leaves Editing/Viewing, collapsed typing, composition, modifier shortcuts, multi-block selections, and selections including deletion-side text on the native path. It neither prevents keyboard events nor buffers/replays characters. It makes no content mutation and schedules no later caret movement. Mount/remount handling follows the public viewport lifecycle; document replacement and unmount clear its state. Unsupported selection application leaves native input in control.

## Verification boundary

Synthetic checks in `server/src/reference-anchors.test.js` cover exact placement, section boundaries, ambiguous anchors, UTF-16/markers, tracked insertion, field rendering, unchanged control text, and cursor-based insertion. `tests/footnote-review-labels.test.mjs` checks the caption guard and unchanged native identity/decision fields.

`tests/reference-integration-portability.test.mjs` checks isolated source boundaries, native dispatch, serialized source mutations, fresh per-prompt context, host mode enforcement, and adapter retry/receipt behavior without adopting the demo runner. `reference-anchor-contract.test.js` checks snapshot anchor variants, nullable normalization, and actionable validation errors. `agent.test.js` exercises the actual agent loop with a scripted model client for corrected retries, repeated failures across inspections, revision changes, malformed arguments, and turn exhaustion. `reference-tool-progress.test.js` checks receipt-only reporting and reference labels. These tests use synthetic metadata and no external API calls.

`tests/tracked-replacement-caret.test.mjs` checks the coordinate conversion, protection against stale repeated ranges during fast typing, guards, and cleanup. A synthetic browser fixture with an earlier pending replacement reproduced the split using trusted pointer selection and keyboard input; the corrected path was exercised at slow and rapid typing rates. Fixture bytes, screenshots, keystroke/selection traces, and exported Word files stay in ignored local artifacts.

Customer reproduction inputs, prompts, exports, traces, and metadata belong in ignored local artifacts. Do not include them in customer integration source. The review-caption adapter still needs a visual check in the consuming application.

Native source reconciliation is covered by real SDK tests in `server/src/citation-import.test.js`: app/native source visibility, source CRUD, native citation insertion, still-cited deletion refusal, original Word tags and opaque XML, duplicate metadata with distinct IDs, formatting, export/reload, and raw SDK persistence. Headless two-client Hocuspocus verification also confirms source visibility in both directions; this is not a browser-rendering or Word-fidelity check.

`full-reference-api.test.js` verifies the five-tool contract, metadata writes in Reviewing mode, batch policy enforcement, real native bibliography lifecycle with APA/Chicago/MLA output, cited-source deletion within batches, and partial receipts. Browser verification confirms source creation and updates by a remote native SDK client appear in the open Citations panel without a reload.
